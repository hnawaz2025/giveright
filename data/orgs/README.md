# Organization corpus

One YAML file per organization. Every fact that reaches a donor -- hours, phone
number, what the org accepts -- is read from here and never generated by a model.

`dev_*.yaml` are synthetic fixtures for development. Real Washington DC
organizations are added on Wed 10 Sep, and each need carries either
`confirmed_by_org: true` (they told us) or a `source_url` plus `last_verified`
(read off their public page). The UI shows which, so a stale fact is visible
rather than silently wrong.

## Fields

| Field | Meaning |
| --- | --- |
| `accepts` | category -> minimum condition (`broken`/`poor`/`fair`/`good`/`new`) |
| `prohibited` | hard refusals; checked before `accepts` |
| `needs[].target_qty` | what a full stock looks like |
| `needs[].on_hand_estimate` | stock the org attested. **Omit it if nobody has said** -- absent means unknown, which is ranked cautiously; writing `0` claims they are empty |
| `needs[].last_verified` | date the fact was last checked; deliveries on or before it are assumed already counted |
| `needs[].shelf_life_days` | how long before the fact is treated as stale |

## This directory is hand-written only

Nothing in `src/` writes these files. Deliveries and organization replies are
appended to `data/observations.jsonl` and replayed on top at load time, so the
sources and comments here survive. An earlier version wrote back to these
files, and one test run replaced a curated file with a machine dump.
